# Native web document imports

Native reads use `src/web/native-service.ts`, a **separate private Worker**. The public API Worker fetches only its internal service binding. The private Worker makes HTTP requests during the import; it has no `R2`, data, model, asset, or other service binding. The snapshot/R2 adapter remains available independently. Neither native configuration nor deployment is enabled by default.

## API

Use a direct User/Admin Data key with `POST /api/v1/resources`. Fields below are in addition to the existing import options (`to`, `parent`, `create_parent`, `wait`, `processing_mode`, etc.); no credentials, refs, table, object selectors, or parser options may be supplied by the client. Use `wait: false` to receive `task_id` and `root_uri`, then poll `GET /api/v1/tasks/{task_id}`. On completion, `documents` contains the indexed resource URIs. Use `/api/v1/content/read` and `/api/v1/search/find` to consume them. For manual imports, collection destinations are create-only. Connector destinations are exact, private `viking://~/resources` paths (or their canonical spelling), with `.txt` for a single object and a new directory for a group.

| Profile | Source fields | Source read / result |
|---|---|---|
| HTML | `path` exact registered URL; `args: {"web_mode":"html"}` | Current HTML, one inert `.txt`. No link traversal. |
| Site | `path` exact registered entry; `args: {"site":true}` | Current HTML and exact approved reachable links, `.txt` folder; `site_limit_reached` on truncation. |
| Sitemap | `path` exact registered XML root; `args: {"sitemap":true}` (also `{"site":true}` for `.xml`) | `urlset` or `sitemapindex`; traverse only registered maps and registered HTML, then `sitemap_limit_reached`. |
| RSS/Atom | `path` exact registered feed; `args: {"web_mode":"feed"}` or `{"feed":true}` | Current feed; title and inline body or explicitly registered article of the first six entries, `feed_limit_reached`. Attachments are not fetched. |
| Git | `add_type: "git"`, `path` approved alias; absent/empty `args` for one file or `{"web_mode":"collection"}` | GitHub Contents `GET`, exact files at one commit, independent SHA-256 pin for each decoded blob. No original `download_url` is called. |
| Feishu/Lark | `add_type: "feishu"`, `path` approved alias or exact registered `/doc`, `/docx`, `/wiki`, `/sheets` or `/base` link; `args: {"web_mode":"native"}` | Native JSON document reads or approved Wiki/Drive file downloads, with permission checked before and after. Sheets use an exact cell range; Bitable uses a registered table and projected columns. |
| Feishu Wiki tree | `add_type: "feishu"`, `path` approved group alias, `args: {"web_mode":"tree"}` | Each approved Wiki document is resolved and its space and parent edge are verified. The declared relative tree is committed and indexed atomically, without discovery. |
| TOS | `add_type: "tos"`, `path` approved alias or exact registered `tos://bucket/key`; `args: {"web_mode":"native"}` | Signed native `GetObject` from the registered region/bucket/key, with operator-mapped TOS read credentials. |
| TOS collection | `add_type: "tos"`, `path` approved group alias, `args: {"web_mode":"collection"}` | Atomic tree assembled from all registered `GetObject` requests, with per-key authorization. No `ListObjects`, open prefix or caller-provided keys. |

The existing `htmlImport`, `siteImport`, `feedImport` and Git flags include native mounts; `liveOriginImport`, `liveFeedImport`, `liveGitDocsImport` and `sitemapImport` distinguish native origin profiles. `feishuNativeImport`, `tosNativeImport`, `feishuTreeImport`, `tosCollectionImport` and `providerWatches` are actor-scoped, independently of `*ArchiveImport`. These report a configured service mount and eligible catalogue entry, **not** a credential or provider readiness probe. Root, OAuth, OIDC and dedicated Gateway keys do not gain these modes. No result includes private binding IDs or headers. The pre-existing Studio HTML/Site/Git path is unchanged; new sitemap, feed, connector and watch selections are HTTP API only here.

## Exact private mounts

1. Use `src/web/native-service.ts` as the entry of a distinct Worker. **Disable every public ingress**: no routes/custom domains, `workers_dev: false`, `preview_urls: false`. No private-network/VPC, internal DNS/host overrides, tunnels or proxy routing. Use the platform's public HTTPS egress only (for self-hosted runtimes, a public-only outbound network with private, loopback, metadata and split-horizon destinations blocked is required). Verify that managed Web/feed hostnames resolve only to public endpoints and remain under approved operator control. Do not register an ingress hostname of this Worker or another internal service, even if it has public DNS. Platform egress restrictions are part of this mount; the TypeScript URL validator is not a DNS/IP filter.
2. Mount that private Worker as `WEB_NATIVE_SOURCE` **only** in the API Worker. Set `OPENVIKING_EDGE_WEB_NATIVE_CATALOG` to the same exact JSON bytes in both environments. The shared catalogue contains identities of operator-approved sources but no credentials. The API Worker passes a fresh GET to `https://web-native.invalid/v1/{revision}/{kind}/{id}` inside the service binding. Both ends verify the exact inventory SHA-256, account, and route provenance; for connectors the receiver also enforces the mapped user. A split update fails before egress. Change the revision and publish matching inventory to both sides when changing scope; queued jobs with a changed inventory fail the existing reservation fence. Never give other callers access to the private binding.
3. Set `WEB_NATIVE_CREDENTIALS` **only in the private Worker's secret store** (JSON array, up to 32 rows). A Feishu secret row has exactly `{id,kind:"feishu",bearer}` with a user-access token for the provider identity explicitly mapped to the registered Edge user and document; grant only document/comment-free read scopes required by the adapter. A TOS row has exactly `{id,kind:"tos",access,secret,session}` (`session: null` for non-STS); use a principal with `GetObject` only on the exact nominated key, ideally short-lived STS. Rotate out of band; missing or expired credentials fail closed. Never configure or export these secrets through `ov.conf`, retention, job payloads, Workspaces, or snapshots.
4. Leave the optional legacy `WEB_SOURCE`/`OPENVIKING_EDGE_WEB_CATALOG` mount unchanged. Native rows take precedence for the exact matching account/mode/path; an admitted native read never falls back to a snapshot. For operational clarity avoid duplicate paths/aliases across the two catalogues. Only the parent/operator should attach a production binding after procurement and verification.

Catalogue: `{version:1, revision, sites, feeds, git, connectors, groups?}`; arrays are limited to 32 rows per family, whole JSON at most 48 Ki characters. `revision` is a 64-character lower-hex operator revision identifier; the protocol also binds the independent digest of the exact file. IDs and aliases have up to 64 lowercase letters/digits/underscores/hyphens and start with a letter/digit. IDs must unambiguously identify a permit within each kind. Reusing a robots ID for the exact same account/origin is allowed. All keys in the tables are required except where noted; use `[]` or `null` where shown.

| Array | Row keys and constraints |
|---|---|
| `sites` | `{account,entry,name,explore,robots,pages,sitemaps,sitemap_entry}`. `robots` is a private ID for this exact origin's `/robots.txt`. `pages`: 1–24 `{id,url,name}` rows with unique URL and `.txt` output name. `entry` equals one page URL. `sitemaps`: 0–8 `{id,url}` rows, XML paths on the same origin. `sitemap_entry` is one such URL or `null` for an empty list. `name` is a destination folder basename; `explore` enables the explicit Site route. |
| `feeds` | `{account,id,url,name,kind,robots}` plus optional `mirror`. `kind` is `rss` or `atom`. `robots` refers to that origin's exact policy; `name` is the destination folder basename. `mirror` contains up to 24 already registered same-origin HTML URLs for this account and robots ID, with unique non-`entry-` basenames. An exact RSS link or Atom alternate link can select one of them. Unlisted, blocked, ambiguous and duplicate links keep inline rendering; admitted articles are read inertly, without following their links. |
| `git` | `{account,alias,name,repository,commit,collection,files}`. `repository` is `owner/repo`, `commit` full 40-character lower-hex commit. `files`: 1–6 exact `{id,file,name,blob_sha256}` records for distinct `.md`/`.txt` paths. With `collection:false`, one file only and outer `name` is a `.txt` name. Otherwise it is a folder basename. |
| `connectors` | `{account,user,id,alias,name,kind,source,target}` plus optional `wiki`, `binary`, `data`, `watch`. `user` is the sole Edge user allowed to import this document; `id` selects the private credential. `kind:"feishu"`: exact HTTPS link; `target:null` for direct links, or the pinned `doc/<token>`, `docx/<token>`, `file/<token>`, `sheet/<token>` or `bitable/<token>` for Wiki. `wiki:{space,parent}` verifies the space and exact parent node (`null` marks the admitted root). `data:{range}` for Sheets (e.g. `Sheet1!A1:B2`, at most 200 rows × 20 columns); `data:{table,columns}` for Bitable (up to 20 approved columns, up to three pages of 100 records). A Wiki Drive `file` requires `binary` with the approved filename. `kind:"tos"`: exact `tos://bucket/key` with ASCII path segments. `target` is the Volcengine region; `binary` is required for nontext and must match the key basename. `watch:true` opts the individual alias into watch registration. |
| `groups` | `{account,user,alias,name,kind,objects,watch}`. Each of 1–16 `objects` is `{id,relative}`: it references an approved connector of the same account/user/kind, with a unique relative `.txt` output beneath the group directory. Feishu requires `wiki` on every item; the first is the approved root, and each child's path must reflect its declared parent (`root.txt` then `root/child.txt`, etc.). TOS paths may be grouped into operator-named subfolders; every object is read independently, up to six subdirectory segments. |

## Provider waves and watches

Set `watch_interval` (minutes, 1–43,200) on a provider request using a **registered alias** and exact private destination. `POST /api/v1/watches` or `POST /api/v1/resources` stores the schedule without a first read. Use the existing get, pause, delete and trigger routes (folder `to_uri` supported). First execution must have an empty destination. An alarm or trigger re-resolves the mounted grant, verifies the stored Data/member epoch and exact operator plan, checks provider permissions on each read, and compares the last published subtree revision. A revoked grant, changed registry selection or manual edit cannot be overwritten. Changed files and index entries, watch revision and manual run receipt commit together; unchanged content does not rebuild its index. Provider failures leave the original tree intact. Watch aliases are not portable data and credentials never enter a row. An operator-plan change requires a new registration; leave prior results intact or explicitly arrange a new empty destination.

The optional `approvedGitPreflight(webSources, alias, collection)` is a local approval descriptor for a future Plans consumer, not a new route, fetch, or Git execution. Call only after mounting the direct Data lease in the same actor context. It accepts no repository/host/ref arguments, returns alias, mode, catalogue revision and file count, and does not imply vendor reachability; any later import must repeat the normal admission checks.

## Protocol and limits

- Managed Web origins use canonical HTTPS domain names and exact ASCII paths, including `/`, extensionless paths and trailing slashes. No literal IP, alternate port, ambiguous normalization, query or fragment. Links and XML `<loc>` elements can select only exact same-origin registered records. The private Worker issues fresh GETs (`cache: no-store`, `redirect: manual`), rejects redirects, mismatched response URL, partial responses and nonidentity encodings; it never relays arbitrary cookies, authorizations or headers. Each public HTML/map/feed GET has a live `robots.txt` recheck immediately upstream; the app additionally uses robots for selection. Missing or unparseable policy fails closed; publish a valid empty policy if the operator wants to explicitly permit all *registered* documents. There is no default-origin discovery or crawl triggered by a `Sitemap:` entry in robots.
- HTML/Site: six pages/two links deep. Sitemap: up to four maps including the root, two levels of nested maps, six unique HTML documents, no DTD or entity resolution. RSS/Atom: same inert parser and six-entry limit as the snapshot path, with optional exact article reads as specified above. No arbitrary article navigation, external XML resources, or execution of HTML. Graph truncations give the corresponding limit receipt; byte/time/provider errors do not masquerade as successful truncation.
- At most 192 KiB of aggregate private reply bytes per import; individual caps 16 KiB robots, 64 KiB HTML/XML/connector text, 96 KiB Git JSON; private service also bounds every raw provider read, includes at most 192 KiB Feishu JSON per connector request, and budgets 7.5 s per binding read. The outer source read is limited to 8 s across policy, checks, reads, and extraction. Repeated private robots checks are individually capped and bounded in number by the six HTML/four map read ceiling. Filesystem maintains its existing quotas, Data lease, destination revisions, task cancellation and transactional publication of tree, search index, and receipt. Provider checks govern import-time only; deleting a provider grant does not erase already stored copies. Do not register documents unless the operator permits retention and indexing in the mapped user's private Edge namespace and configured embedding path.
- Feishu: fixed API hostname for the vendor suffix. `get_node` must match the approved node/object and, for a tree, space/parent before and after that object's read; no `nodes` list, directory discovery or external shortcut traversal. Drive member `auth_result` must be `true` before and after the read. Legacy uses `/doc/v2/{id}/raw_content`, and DOCX projects bounded pages of blocks: headings, lists, code, quotes, todos, callouts, dividers, equations, plain mentions and simple tables (100 cells). Sheets uses the exact `values/{range}` result; Bitable uses `records` with registered `field_names`. Values are inert scalar/rich-text projections; unsupported blocks or selected values fail rather than produce a misleading partial document. Child transfers are not a distributed provider transaction: ACLs and Wiki edges are checked per member, and the final Edge write is atomic and fenced by the local grant.
- TOS: each `GET https://{bucket}.tos-{region}.volces.com/{key}` is signed with `TOS4-HMAC-SHA256` (STS supported); no listing, credential fallback or cross-region redirect. The authorized GET checks provider permissions. `401`/`403` returns generic `SOURCE_DENIED`, not the provider payload.
- Binary imports accept only PDF, DOCX, XLSX, PPTX, PNG and JPEG (JPG alias) via the existing explicitly mounted `OPENVIKING_EDGE_DOCUMENT_CONVERSION=1`/`AI` converter. If unmounted, the operation fails before provider contact. Gross caps: 1 MiB per binary and 2 MiB aggregate (separate from 192 KiB text wire); existing MIME/magic checks, account/user conversion quotas and filesystem size guards still apply. Only converted text is published. No old Office `.doc/.xls/.ppt`, generic archives, HTML, video/audio files, GIF, BMP, WebP or nonconvertible vendor exports; the pin's Mindnote, whiteboards, independent Slides export jobs, embedded Sheet/media and attachment crawls, formatted/merged-table fidelity and arbitrary link expansion are not enabled. Operator approval must permit sending approved binary input to the mounted converter, and retention/indexing of the resulting text.
- Pin `000f0765d7ec183886fbabbc22e69bc289cc429d`: see `openviking/parse/accessors/feishu_accessor.py` (`_probe_document_permission`, Wiki resolution, `_fetch_legacy_doc_raw_content`, `_fetch_all_blocks`, `/open-apis/drive/v1/files` download, Sheets range and Bitable records), `web_feed_accessor.py` (`_collect_entries`), `openviking/connector/routing.py` and `delegate.py` (TOS hand-off). The upstream TOS path delegates to a separate Connector. This Worker reads exact registered individual objects **and collections** without exposing that Connector's general API. General provider discovery, Git clone/private Git and source-rule grants are not supported. Vendor scopes, public egress and actual production mounts remain operator prerequisites, not claims from the intercepted suite.
