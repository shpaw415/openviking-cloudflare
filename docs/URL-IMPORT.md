# One-time URL import on Edge

The reference is OpenViking `000f0765d7ec183886fbabbc22e69bc289cc429d` (`docs/en/api/02-resources.md`, `openviking/server/routers/resources.py`, `web-studio/src/features/workbench/resources`). The missing pieces in B3 were destination inference, `parent`/`create_parent`, and entry through the real Studio form. B3 already supported explicit text-file URL imports and watches; scheduling is not a new feature.

## Operator boundary

- `features.urlImport` is a JSON boolean. It can be true only for a direct User/Admin Data API key when Control, the Workspace, the embedding transport, and the operator's `TEXT_SOURCE` binding with at least one eligible entry in `OPENVIKING_EDGE_TEXT_SOURCES` are mounted. It is not a health probe, a guarantee of quota or an ACL grant. The Studio reads it for the current Workspace connection. Root and dedicated Gateway credentials do not gain data access; the OAuth and OIDC restrictions do not change. If Control cannot confirm current Data authority, the import fails closed before the next provider or publication effect.
- Mount `TEXT_SOURCE` only as an operator-owned, narrow approved-document service. It must independently return a vetted public text document for an exact URL key (prefer a fixed document map), not act as a generic fetch proxy, follow redirects, or resolve arbitrary destinations. This change does not ship such an external service, configure a real binding, or verify real DNS/address policy. Without the binding there is **no direct network fallback** in one-time import. Existing watch configuration and transport remain separate and unchanged.
- The configured list is JSON, at most 64 strings and 32,000 characters. The request must match an exact canonical HTTPS document URL in that list. A DNS-style name, visible ASCII path segments and a `.md`, `.txt`, `.csv` or `.json` leaf are required. Credentials, queries, fragments, IP literals, local host labels, explicit ports and directory URLs are not admitted. The client cannot set fetch headers or credentials. The Worker sends a fresh GET with a fixed `Accept`, does not follow redirects and does not make follow-up requests to links in the content. If there is no eligible mount the route returns `501`; a well-formed but unapproved URL on a mounted service returns `503`.
- The binding has an eight-second deadline covering both headers and body. Only a full `200` response with an admitted content type, identity encoding and valid non-blank UTF-8 (at most 64 KiB, with or without a UTF-8 BOM) is accepted. JSON bodies requested or labeled as JSON must parse. HTML, media, executables, archives, remote skills/plugins and directory/repository/feed crawling are out of scope. No active HTML parser or semantic generation runs on these imports.

## API and Studio

`POST /api/v1/resources` with `{ "path": "https://documents.fixture.test/handbook/compass.md", "wait": true }` imports the approved document under `viking://resources/` if writable. The final leaf is derived from the source URL. `parent` selects a different shared or own-private resource directory; `create_parent: true` permits creation of missing ancestors in that scope. Automatic naming suffixes writable collisions (`compass_1.md`, etc.); an ACL refusal or reservation conflict stops the import instead of bypassing that entry. `to` (or legacy `to_uri`/`uri`) can name one exact visible text file; it cannot coexist with `parent`, replace a directory or erase descendants. An authorized, fenced overwrite preserves the existing ACL and tags. An identical indexed file needs no rewrite. `strict` does not weaken the all-or-nothing policy. `args.parse_mode: "default"` and `"no_split"` both keep one text body; other parser/connector options and body ACL/tag edits are not part of this route. `processing_mode: "vectors_only"` states what is done; the legacy semantic mode is accepted with an explicit no-summary warning. Compatibility `timeout` and `telemetry` are accepted, but they cannot modify the source deadline.

- `wait` omitted or true returns the committed URI and `status: "success"`. A `wait: false` POST returns `status: "accepted"`, `task_id` and the reserved `root_uri`. Follow `GET /api/v1/tasks/{task_id}` to the terminal result. The task keeps the Data authority revisions of its account and member as admitted at submission, in addition to its target reservation and actor. Rotating another member's credential does not invalidate it. The Worker checks the durable Workspace floors before source I/O, before embedding, and inside the SQLite transaction that publishes folders, content, vectors and the completed task. No new success after revocation; an effect already started at the provider is not undone. A model configuration change alone does not revoke Data authority. Old one-time URL jobs without an authority revision fail closed and must be submitted again; schedules and staged-file imports are unchanged. Unlike the original server's async non-Git path, Edge acceptance does not imply that the file already exists.
- In **Filesystem → Add Resource**, a positive capability exposes the existing URL tab and destination controls. Leave destination blank to use private `viking://~/resources`; other choices are an existing resource folder or an exact file URI. The dialog follows the actual `add_resource` job and keeps the error visible on refusal. It never falls back to local upload, opens a third-party login or asks for another key. The original local upload tab remains. No web crawler, watch creation or advanced parser controls are offered in the one-time Edge tab. Editing the Workspace connection discards outstanding replies from the old UI scope; it does not undo an already committed server mutation.
