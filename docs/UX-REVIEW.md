# Revue indépendante du Web Studio sur le Worker Cloudflare

**7/10 — parcours principal validé sur le Workerd local corrigé ; modifications UX demandées.** La connexion User, l’exploration et l’ouverture d’un résultat fonctionnent. Le focus du champ de recherche, les contrastes de ses états et la présentation des capacités indisponibles restent à corriger. Le précédent 5,5/10 était une appréciation source seule, avant ce bundle et la contre-visite.

L’administration, la frise, l’éditeur et les imports ne sont pas audités comme fonctionnalités. Référence : checkout amont réel et sans changement suivi signalé, SHA `000f0765d7ec183886fbabbc22e69bc289cc429d` ; `.work/studio/CONTRAT.md`, `upstream/web-studio/README.md`, `CONTRIBUTING.md` et `docs/frontend-structure.md`. React/Vite/TanStack Router, Tailwind/shadcn, i18next EN/zh-CN. Les six domaines `better-*` ont été chargés.

Le parent a livré le build **Vite seul sous Node 22** et les deux instances loopback via `scripts/studio-smoke.mjs` : Workerd réel et Durable Object SQLite jetable, **seul le binding d’IA est remplacé par une fixture** sans service distant. `dist/studio/index.html` et la réponse de `8799/studio/index.html` donnent tous deux le SHA-256 `686594e0c4c058b4cee4626772db2187e531725ed7053e16475ece44ac102967`, avec `index-UpWspZeC.js` et `index-DgnabT0F.css`. Je n’ai pas relancé le build ou la suite de tests du parent. Preuves dynamiques ci-dessous relevées dans mon propre Chrome, sans capture ni sortie de valeur de clé.
